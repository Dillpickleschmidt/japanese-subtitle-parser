### ⚠️ Marked Undetectable: という1 (every single A)

**Grammar Point**: という1
**JLPT Level**: N1
**Priority**: 5 (not implemented)
**Structure**: Noun (A) + という + Noun (A) - where BOTH nouns must be IDENTICAL

**Undetectable Reason**:
This pattern requires **cross-token validation** (checking if token[0].surface == token[2].surface).
The current TokenMatcher architecture only allows matchers to examine one token at a time via the
`Matcher` trait's `matches(&self, token: &KagomeToken)` method.

**Technical Details**:
- The `match_pattern_at()` function processes tokens sequentially
- Each TokenMatcher only receives the current token being matched
- No mechanism exists to compare tokens at different positions in the pattern
- Implementing this would require:
  1. Adding a new TokenMatcher::MatchesPrevious { offset: isize } variant
  2. Modifying match_pattern_at() to track previously matched tokens
  3. Extending token_matches() to accept match history
  4. This represents a significant architectural change

**Workaround**:
- The basic という pattern (priority 1) already matches "Noun + という + Noun" structures
- Users can see という detected at the correct range
- They should manually check if both nouns are identical to determine meaning:
  - Identical nouns → という1 (every single A)
  - Different nouns → basic という (A called B)

**Examples that CANNOT be distinguished**:
- 床という床 = "every single floor" (という detected, but not という1 specifically)
- 電柱という電柱 = "every single telephone pole"
- 道という道 = "every single road"
- 今日という今日 = "today of all days"
