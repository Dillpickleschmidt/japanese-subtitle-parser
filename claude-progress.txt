### 🔍 Investigation: のではないだろうか (I think, isn't it?, don't you think?)

**JLPT Level**: N2
**Category**: Construction
**Priority**: 4
**Status**: TODO - Needs further investigation

**Pattern**: のではないだろうか is a rhetorical question construction expressing opinions indirectly. Translates as "I think it's (A), isn't it?" or "it might be that (A)". Combination of の + ではない/じゃない + だろう/でしょう + か.

**Pattern structures** (from grammar_points_data.json):
1. Verb + の/ん + ではない/じゃない + だろう/でしょう + か
2. い-Adjective + の/ん + ではない/じゃない + だろう/でしょう + か  
3. な-Adjective + なの/なん + ではない/じゃない + だろう/でしょう + か
4. Noun + なの/なん + ではない/じゃない + だろう/でしょう + か

**Tokenization observed**:
- のじゃない form: の (名詞/非自立) + じゃ (助詞/副助詞) + ない (助動詞) + だろ (助動詞/未然形) + う (助動詞) + か (助詞)
- のではない form: の (名詞/非自立) + で (助動詞/連用形) + は (助詞/係助詞) + ない (助動詞) + でしょ (助動詞/未然形) + う (助動詞) + か (助詞)
- なのでは form: な (助動詞/体言接続) + の (名詞/非自立) + で (助動詞/連用形) + は (助詞/係助詞) + ない + でしょ + う + か

**Critical discovery**: token.features vs token.pos
- KagomeToken has both `pos: Vec<String>` and `features: Vec<String>`
- Based on codebase patterns, `token.features` should be used for accessing feature array
- Other matchers in the codebase use `token.features.get(4)`, `token.features.get(5)`, etc.
- Feature indices:
  - features[0] = part of speech (助動詞, 助詞, etc.)
  - features[1] = subtype (副助詞, 係助詞, 特殊・ダ, etc.)
  - features[4] = conjugation type (特殊・ダ, 特殊・ナイ, etc.)
  - features[5] = conjugation form (未然形, 連用形, 体言接続, 基本形, etc.)

**Implementation challenges**:
1. Multiple custom matchers needed (NoNMatcher, JaDeMatcher, HaParticleMatcher, NaiAuxMatcher, DaroDeshoMatcher, UMatcher, KaFinalMatcher, NaCopulaMatcher)
2. TokenMatcher::Any needed at start to match preceding verb/adjective/noun
3. Optional matchers for な (na-adj/noun forms) and は (では vs じゃ distinction)
4. Feature index mapping was initially incorrect (using features[1] instead of features[4]/features[5])
5. Even after correcting feature indices, pattern matching had issues
